# 06 — AI assistant

## 1. Role and limits

The AI **suggests**; the user (or a user-enabled rule) **decides**.

- Writes to user data only through: (a) `ai.suggestion` fields on an item, (b) applying a
  suggestion the user accepted, (c) auto-apply when `settings.ai.autoApply.enabled` and
  `confidence ≥ minConfidence`, limited to the configured fields, (d) applying an
  assistant action card the user clicked.
- Never deletes, archives, changes projects/tasks status, or touches Accounts.
- Every AI write records `ai.provider`, `ai.model`, `ai.updatedAt`; Undo is available.
- Order of organisation: **rules → AI → user**. Rules always run first and AI receives the
  rule results as context ("already set by rules: area=Dev Resources").

## 2. Provider abstraction (`lib/ai/`)

```ts
interface AIProvider {
  id: string;                         // settings providerId
  type: "gemini"|"groq"|"openrouter"|"openai-compatible"|"anthropic";
  generateJSON<T>(req: { model: string; system: string; user: ContentPart[];
                         schema: ZodType<T>; maxTokens: number; temperature?: number;
                         timeoutMs: number }): Promise<{ data: T; usage: Usage }>;
  streamChat(req: { model: string; system: string; messages: ChatMessage[];
                    tools?: ToolDef[]; maxTokens: number; timeoutMs: number }): AsyncIterable<ChatEvent>;
  supportsVision(model: string): boolean;
  ping(model: string): Promise<{ latencyMs: number }>;
}
type ContentPart = { type: "text"; text: string } | { type: "image"; mime: string; base64: string };
```

Adapters (use `fetch` directly; avoid heavy SDKs):
- **Gemini:** Google AI `generateContent` / `streamGenerateContent`, `responseMimeType:
  "application/json"` + `responseSchema` (converted from Zod via `zod-to-json-schema`).
- **Groq, OpenRouter, OpenAI-compatible:** `/v1/chat/completions` with
  `response_format: { type: "json_object" }` (or `json_schema` where supported) and tools.
- **Anthropic:** Messages API with tool-use for structured output.

Per-task model choice lives in `settings.ai.taskModels`. Suggested starting picks (verify
what is free when you set up; free models and quotas change often):

| Task | What it needs | Suggested class |
|---|---|---|
| classify | Cheap, fast, JSON | Small "flash-lite"/8B-class model (Gemini Flash-Lite, Groq Llama 8B-class) |
| summarize | Good reading, short output | Flash-class model |
| extract (tasks/dates) | JSON reliability | Flash-class model |
| vision (screenshots) | Image input | A Gemini Flash-class model with vision |
| chat | Reasoning + tool calls | Best free chat model available (Groq or OpenRouter free, or Gemini Flash) |

**Robustness:** timeout 15 s (chat stream 30 s); on invalid JSON → one repair retry
("Return only valid JSON for this schema"); on 429 → `RATE_LIMITED` with `retryAfter`;
optional fallback provider per task (`fallbackProviderId`). Truncate inputs: title 300,
description 1 000, note 4 000, selection 2 000, OCR 3 000 chars.

## 3. Tasks, schemas, prompts

### 3.1 `classify` + `summarize` → `SuggestionSchema`

```ts
const SuggestionSchema = z.object({
  title: z.string().max(120).optional(),
  description: z.string().max(400).optional(),        // what it is, 1–2 sentences
  summary: z.string().max(1200).optional(),           // only when content is long
  kind: z.enum(["link","note","idea","decision"]).optional(),
  areaId: z.string().optional(),                      // must be one of provided ids, else dropped
  tags: z.array(z.string().max(40)).max(6).optional(),// prefer existing tags
  tasks: z.array(z.object({ title: z.string().max(200), due: z.string().optional() })).max(5).optional(),
  confidence: z.number().min(0).max(1)
});
```

System prompt (classify):
```
You organise items in a personal knowledge hub for a software engineering student and
freelance web developer in Pakistan. Output JSON matching the schema only.
Rules:
- Choose areaId ONLY from the provided areas list. If unsure, omit it.
- Prefer existing tags; create a new tag only if none fits. Lowercase, kebab-case, max 6.
- description: plain, factual, 1–2 sentences: what this is and why it might be useful.
- Do not invent facts that are not in the input. If the input is only a URL with no
  content (e.g. an Instagram reel behind a login wall), describe only what can be inferred
  from the URL/platform and the user's note, and lower confidence.
- tasks: only if the user's note or the content clearly implies an action.
- confidence: your confidence that area and tags are right (0–1).
```
User content template:
```
Areas: [{id, name}] · Existing tags (top 100 by use): [...]
Already set by rules: {areaId?, tags?}
Item: kind={kind} platform={platform} url={url} domain={domain}
title={title}
page description={description}
user note={note}
selected text={selection}
image text (OCR)={ocrText}
```

### 3.2 `extract` (tasks and dates from a note) → `{ tasks: [{title, due?}] }`
Used by "Make tasks from this note" action and Assistant.

### 3.3 `vision` → `{ ocrText, description, suggestedTitle }`
Prompt: transcribe visible text faithfully (keep URLs, handles, prices, dates), then
describe the screenshot in 1–2 sentences, suggest a short title. Never identify real
people from faces.

### 3.4 `chat` (Assistant)

System prompt:
```
You are the assistant inside the user's PersonalHub. You help them understand things they
found (tools, platforms, opportunities), find things they saved, and organise them.
- Use the provided hub items as your memory; cite them by title. If they don't contain the
  answer, say so.
- When the user shares a URL, use the provided page metadata. If it's thin, say what you
  know generally and flag uncertainty. Never claim you visited a page you weren't given.
- You can PROPOSE actions with the tools. Proposals are applied only if the user clicks
  Apply. Never claim an action is done.
- Be concise. Pakistani context matters (PKR, PKT time zone) when relevant.
- Never ask for or repeat passwords, API keys, OTPs or recovery codes.
```
Tools (proposals only): `create_item{url?, title, kind, areaId?, tags?, description?, note?}`
· `update_item{itemId, fields}` · `create_task{title, due?, projectId?, itemId?}` ·
`create_project{name, areaId?, problem?, goal?}`. The server converts tool calls into
`actions[]` with status `proposed`.

Retrieval (v1, no embeddings): client runs MiniSearch over the user's query + URL domain,
sends top 8 item ids; server loads those items (excluding areas with `aiAllowed:false` and
never Accounts) and passes compact JSON (title, kind, area, tags, description, note ≤
800 chars, url).

## 4. Triggers

| Trigger | Default | Calls |
|---|---|---|
| After capture | `suggestOnCapture` (default **off** until a provider is configured; then on) | classify (+vision for images) |
| Inbox "Ask AI"/"Process with AI" | manual | classify |
| Item "Regenerate" | manual | classify + summarize |
| Assistant message | manual | chat |
| Import | manual opt-in per import | classify, throttled |

## 5. Budget and rate limits

- Server: `rateLimits/{uid}_{minute}` ≤ 10 AI calls/min; `aiUsage/{date}.requests` ≤
  `dailyRequestLimit` (default 150). Over limit → `RATE_LIMITED`; UI shows when it resets.
- Client batch runner (Inbox/Import): sequential, 1 request at a time, waits `retryAfter`
  on 429, pause/resume.
- Skip AI when nothing to work with (bare URL with `unfurl.status = "blocked"` and empty
  note) unless the user explicitly asks — classify by rules + platform instead.

## 6. Privacy

- Settings shows: "Free tiers of some providers may use your prompts to improve their
  products and may allow human review. Turn off AI for areas with private content."
  (Gemini free tier states this as of 2026; verify each provider's current terms.)
- Areas have `aiAllowed`; default **off** for Personal and Finance.
- Accounts are hard-excluded from every AI path (server check, not just UI).
- AI keys: AES-256-GCM encrypted at rest (server secret), decrypted only inside the
  route handler for one request, never logged, never sent to the client after saving.
- No item content in server logs; log only ids, task, provider, latency, status.
